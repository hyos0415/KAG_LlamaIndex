# 이력서 문장 초안 (KAG_LlamaIndex / News Arena)

> 실측 수치는 `docs/design-review.md`(특히 §4, §7)를 원본으로 한다. §7.2의 한계와 모순되지 않도록 과장된 표현을 배제했다.

---

## 초안

- **Airflow ETL + 하이브리드 검색(BM25+벡터, RRF) + LlamaIndex PropertyGraphIndex 기반 뉴스 분석 파이프라인 구축**
  Airflow 오케스트레이션, Elasticsearch(BM25)·ChromaDB(벡터) 앙상블 검색(RRF 결합), LangGraph 워크플로우, Neo4j 연동 PropertyGraphIndex로 구성된 엔드투엔드 뉴스 분석 시스템을 설계·구축.

- **도입 근거를 사후 검증: 문서 규모(5→40건), 관계 정규화, 엔티티 정규화를 순차 소거하여 조각화 원인을 추출 방식으로 좁힘**
  완성 후 방치돼 있던 시스템의 지식그래프 도입 근거("LLM 응답 비일관성")가 한 번도 검증된 적 없다는 점을 발견하고 사후 진단을 설계·실행. 문서 규모를 5→40건으로 늘려도 entities_per_doc이 오히려 −2.0% 악화됨을 확인해 규모 요인을 배제했고, 관계 타입 정규화(활용형·조사 제거)는 374→358종(4.3% 감소)에 그쳐 효과가 미미함을 실측. 직접 substring 교차문서 쌍 193개 중 40개를 고정 시드 표본으로 수작업 판정한 결과 유의미한 별칭이 0건이어서 엔티티 정규화 가설도 기각. 네 층위 소거를 거쳐 원인을 자유 스키마 추출 방식으로 좁혔으며, 코퍼스 구성(주제 분산)과는 이번 데이터로 분리되지 않아 "확정"이 아닌 "주 원인으로 추정"으로 명시.

- **판정 기준을 측정 전 커밋으로 사전 등록. 기준 결함 3건을 이력으로 특정하고 정정**
  모든 판정 기준(게이트 임계값, 가설 판정 규칙, 표본 중지 규칙 등)을 실행 전에 git 커밋으로 사전 등록하는 방법론을 적용. 실행 후 기준 자체의 설계 결함 3건(교차문서 지표의 조합론적 인플레이션, 노드 병합의 기계적 컴포넌트 감소, 관계 정규화의 그래프 연결성 무관성)을 발견해 커밋 이력을 근거로 투명하게 정정 — 결과를 사후에 합리화하지 않고 무엇이 언제 왜 틀렸는지 문서화.

- **측정 전에 기록한 예측이 적중 — 진단 모델의 예측력 확인**
  날짜 리터럴(예: "5일"="2026년 2월 5일") 병합이 전혀 무관한 두 기사를 그래프상 연결시킬 것이라는 예측을 측정 전에 문서로 기록하고, 실측으로 정확히 검증 — 진단 절차가 사후 설명이 아니라 사전 예측력을 가짐을 실증.

## 사용 시 주의

- 위 문장들은 "AI 시스템의 정성적 우수성 입증"이 아니라 **진단 방법론(사전 등록, 소거법, 예측 검증)** 자체를 강조하는 방향으로 작성됐다 — 원래 README의 "Context Precision 1.0", "할루시네이션 제어" 같은 과장된 성과 문구와는 다른 결이다.
- 지원하는 직무가 "성과 중심"을 요구한다면 첫 번째 문장(파이프라인 구축)만 남기고 나머지는 축약하는 것을 고려할 것.
- 숫자를 인용할 때는 항상 표본 크기(40건, 5건, 표본 40쌍)를 함께 밝힐 것 — §7.2(d) 참고.
