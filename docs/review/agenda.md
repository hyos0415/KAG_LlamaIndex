## 1. "왜 이 기술이 필요한가" — handoff §19 의 핵심 질문

### 1.1 Graph 필요성 반증 게이트 `[C B7]` `[X 블로킹1]`

`condition_omission` 이 Graph 로 풀 문제라는 전제가 미검증이다. 반대 가설 4개와
각각의 반증 실험이 제시됐다. **GPT 과제: 각 baseline 의 선행 사례를 조사해
"이미 알려진 답"이 있는지 확인하라.**

| 반대 가설 | 조사 질문 | 상태 |
|---|---|---|
| 프롬프트/디코딩 편향 | 필수조건 열거를 먼저 시키는 2단계 프롬프트가 entailment 과제에서 효과를 보인 사례가 있는가 | `미조사` |
| claim 분해 단위 | 필요조건/충분조건을 분리한 atomic claim 설계 선례 | `미조사` |
| evidence 검색 리콜 | oracle evidence vs retriever evidence 로 recall ceiling 을 분리한 평가 관행 | `미조사` |
| 결정론적 체크리스트 | 자연어 조건을 checklist 파서로 처리한 금융/법률 도메인 사례 | `미조사` |

> 이 중 **oracle evidence 는 선택이 아니라 필수 통제군**이다 `[X M2]` —
> 기존 저장소는 `LLMRerank(top_n = top_k//2)` 로 검색 문서의 절반을 버렸다.
> "증거 리콜 부족"은 가설이 아니라 코드로 확인된 실패다.

### 1.2 순환성 — 실패가 앞단으로 이동하는가 `[C B8]`

Verifier LLM 이 "claim 에 안 적힌 필수조건을 능동적으로 찾지 못한다"면, 같은 LLM 이
`spcl_cnd` 에서 ConditionGroup 을 완전하게 추출한다는 보장은 어디서 오는가.

**GPT 과제**: 구조화 추출(structured extraction)이 자유형 추론보다 같은 모델에서
더 완전한 결과를 내는 조건이 문헌에 정리돼 있는가. 스키마 제약이 recall 을 올리는가
내리는가.

무제약 추출의 실측 기준선 `[A §3.4]`:

```
허용 타입 0 · 출력 언어 미제약(영문 라벨 83종) · 리터럴/개체 미구분
엔티티 경계 미정의(이름 52%가 복합구) · 파싱 실패 조용히 폐기, 계측 없음
```

## 2. schema 및 실험 설계 검토 — handoff §14

### 2.1 노드 / 리터럴 / 논리식 구분 `[X C3, M1]`

두 감사가 독립적으로 같은 요구에 도달한 항목. 실측 근거:

```
리터럴 형태 엔티티 노드      152 / 925 = 16.4%
목적어가 리터럴인 트리플      183 / 773 = 23.7%
교차문서 브릿지 중 리터럴        6 / 42  = 14.3%
```

**GPT 과제**: 금융/법률 도메인 Rule Graph 에서 수치·기간·비율을 노드로 두는 설계와
리터럴 속성으로 두는 설계의 선례를 조사하라. RDF/property graph 관행 차이 포함.

### 2.2 operator 층위 `[C B11]`

`ALL_OF/ANY_OF/NOT`(논리 결합자) · `THRESHOLD/TEMPORAL`(비교 제약) ·
`EXCEPTION`(scope override) · `MUTUALLY_EXCLUSIVE`(consistency 제약)가 한 enum 에 섞였다.

**GPT 과제**: 조건 논리를 표현하는 기존 형식(SHACL, Datalog, LegalRuleML, DMN,
Drools 등)이 이 네 층위를 어떻게 분리하는지 조사하라. 바퀴를 다시 만들 필요가 있는가.

### 2.3 집합 차분의 붕괴 지점 `[C B9]`

`Required - Claimed` 가 깨지는 7종: 패러프레이즈 / 함의 조건 / k-of-n / threshold·range /
예외 / 중첩 / claim 의 부정.

**GPT 과제**: 이 7종 각각이 실제 `spcl_cnd` 문구에서 어떤 빈도로 나타나는지 —
금융상품 한눈에 API 샘플로 추정하라. **빈도가 낮은 유형은 MVP 에서 빼도 된다.**
이 조사가 §8 격하 범위를 정한다.

### 2.4 Graph-only 의 지위 `[C B12]`

Graph 가 `UNSUPPORTED 후보`만 낸다면 3-way classifier 비교가 성립하지 않는다.

**GPT 과제**: abstaining classifier / selective prediction 평가 관행 조사.
coverage 밖 사례를 어떻게 채점하는가.

### 2.5 데이터셋 구축과 검정력 `[C B14]`

handoff 에 데이터셋 크기·negative 사례 출처·검정력 계획이 없다.

**GPT 과제**: 이 규모(개인 프로젝트, 은행권 정기예금 단일 도메인)에서 유의미한
차이를 검출하려면 최소 몇 건이 필요한가. 사례 몇 건으로 발표 가능한 주장을 한
선행 연구가 있는가.

## 3. failure interpretation — 기존 프로젝트에서 무엇을 배웠나

### 3.1 정규화가 답이 아니었다는 것의 서사적 의미 `[X D2]`

handoff §2.1 은 "정규화 규칙이 없었다"를 개선 가능한 결함으로 나열한다. 그러나
이 저장소는 정규화를 실제로 시도해 **기각**했다 — 재등장 엔티티가 925개 중 42개(4.5%)뿐이라
완벽한 별칭 사전의 상한이 이미 낮다.

**GPT 과제**: 이건 "실패"인가 "발견"인가. 포트폴리오 서사에서 어느 쪽으로 쓰는 것이
정직하고 동시에 강한가. `docs/review/narrative.md` 와 연동.

### 3.2 이관 자산이 코드가 아니라 규율이라는 것 `[X C2]`

두 감사가 독립적으로 도달한 판정. 사전 등록 · 예약된 반증 조건 · 처치를 성과로 읽지 않기.

**GPT 과제**: 이 규율을 "포트폴리오에서 보여줄 것"으로 서술할 때, 실험 결과가
전부 기각(negative result)인 프로젝트를 어떻게 제시하는가. 선례 조사.
