# IDEA_RESOLVED — 결론이 난 것

## 이 디렉토리의 지위

`IDEA_CLAUDE/` · `IDEA_GPT/` 의 원문 중 **결론이 난 것**만 여기 온다.
여기부터 진실이며, 다른 문서가 근거로 인용할 수 있다.

## 쓰는 주체

**Claude Code 만 쓴다.** 앱은 여기에 쓰지 않는다.

## 승격 규칙

1. 원문의 출처 머리글을 정규화한다 (없으면 대화 맥락에서 복원해 채운다)
2. 파일명을 `YYYY-MM-DD-<주제-슬러그>.md` 로 정규화한다
3. handoff §16 의 4항목 형식으로 변환한다

```
Decision       무엇을 정했나 (한 문장)
Evidence       왜 그렇게 정했나. 측정값이나 파일:줄 인용. 없으면 "근거 없음 — 판단"
Alternative    검토한 다른 선택지
Why rejected   각 대안을 왜 버렸나
반증 조건       무엇이 관측되면 이 결정이 틀린 것인가 (결정 시점에 미리 적는다)
```

4. 원문 파일은 인박스에 그대로 남긴다 — 삭제하지 않는다. `출처` 칸에 원문 경로를 적는다
5. **승격 직후 커밋한다.** 예외 없다

5번이 규칙인 이유: 승격은 "검증 안 된 것"이 "진실"로 바뀌는 지점이다. 그 전환이
커밋되지 않으면 언제 무엇이 근거로 승격됐는지 추적할 수 없고, 이 저장소가 이미
두 번 겪은 재현성 실패(`docs/CONTEXT.md` 발견 11·20)와 같은 모양이 된다.

## `docs/spec/` 과의 경계

| | 무엇 |
|---|---|
| `IDEA_RESOLVED/` | **결정 기록.** 언제 무엇을 왜 정했나. 감사 추적용 |
| `docs/spec/` | **명세 문서.** 그 결정들이 반영된 결과물. 신규 저장소로 이관될 초안 |

같은 내용이 두 곳에 중복되는 것이 정상이다 — 하나는 이력, 하나는 현재 상태다.
충돌하면 `IDEA_RESOLVED/` 의 최신 결정이 우선하고 `docs/spec/` 을 갱신한다.

## 내용 충돌

두 앱이 같은 주제에 다른 결론을 내면 **사람이 조정한다.** Claude Code 가 임의로
한쪽을 고르지 않고, 양쪽을 나란히 제시하고 물어본다.
